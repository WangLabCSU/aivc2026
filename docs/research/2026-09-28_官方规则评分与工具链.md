# VCC 2026 官方规则、评分与工具链调研

> 调研日期：2026-09-28 ｜ 调研人：ZCode agent A ｜ 状态：已核实官方页面

## 1. 规则要点（已核实）

- 时间线：8/20 开放提交；**10/22 发布最终测试集**（D/E/F 新细胞系+新扰动面板）；**11/5 23:59 UTC 截止**；11 月下旬颁奖。来源：https://arcinstitute.org/news/virtual-cell-challenge-2026
- 每日限额：榜单与最终提交均**每天最多 2 次**（UTC 零点重置）；被拒/未计分提交不占额度；同队同时只能 1 个在途（409）。仅**最后一次**最终提交计奖。
- 团队：每队 **≤8 人**；机构可多队（成员不重叠）；注册需资格确认+ selfie 人 Verification；无报名费。
- 方法描述：不要求交代码；**入围 finalist 后必须提交可公开的方法描述**（训练数据、处理、模型、非学习组件、训练/推理方案，可选算力）。
- 奖金：总 $175k（$100k/$50k/$25k，现金+NVIDIA Brev 积分）。
- 训练数据 FAQ 原文："As long as you have the appropriate permissions to use the data, you may use any data… This includes proprietary data"；可用 State/Stack 代码与非商业权重；**禁止**把实验/文献结果直接塞进提交或修正模型输出，**允许**用于训练/微调。2026 无官方训练集，纯零样本。来源：https://virtualcellchallenge.org/faq

## 2. LLM 提交（重点查证结论）

- **无独立"LLM 赛道"**，但 **2026-09-16 规则修订**：删除了旧条文 "predictions must be generated solely by one or more machine learning models"；新条文只禁止提交实验/文献结果或用其修正预测。→ **允许 LLM/启发式直接生成计数矩阵**（只要不是抄真实数据）。来源：https://virtualcellchallenge.org/rules（"Submitting Final Entries" 一节）
- **官方 CLI 内置 agent skill**：`vcc skill install` —— "If you use a coding agent (Claude Code, Codex, Gemini), the CLI can install a skill so your agent can drive the whole workflow"。装后可直接对话式下单（"download the VCC control data and make a submission"）。来源：https://vcc-cli-wiki.virtualcellchallenge.org/ 、https://virtualcellchallenge.org/evaluation
- FAQ："Can I use proprietary models or data?" → "Yes, so long as you have the right to do so."
- 官网 JS 源码逐字检索无 "LLM" 专门条款；`vcc skill install` 的 skill 内容在 PyPI wheel 内；GitHub 无 vcc-cli 开源仓库。

## 3. 评分体系（已核实）

- 打分器：**cell-eval2** 的 `vcc2026` profile，10 个成员指标中 **6 个计分**：
  - `pds_cosine`（面板内扰动排名可分性）
  - `expr_mse_unbiased_capped_norm`（唯一 0–1 封顶）
  - `de_wilcoxon_direction_fidelity_raw`（fid，可低至约 −1.9）
  - `direction_reach_raw`（reach）
  - `sig_jaccard`（jac，下限约 −0.1）
  - `lfc_nmae`（nmae，罚帽 −6）
  - DE 用 Wilcoxon+BH FDR 0.05；被打低的靶基因自身行从全部指标剔除。来源：https://github.com/ArcInstitute/cell-eval2
- 标度：每指标按各自 context 两锚点缩放——**0 = 该 context 细胞均值基线，1 = 真实重复实验**（五个对半 split 的均值）；Overall = 六指标无权平均 → 3 context 平均；可 >1 也可为负。
- **验证榜与最终榜不可比**（不同细胞系/面板/锚点）。
- **"naive baseline ≈0.85" 未查到官方出处**，属社区传闻；wiki 演示输出 "Rank 2, Overall 0.3614"。建议以自家 LOCO 复算为准。

## 4. vcc CLI 与 .vcc 硬约束

- PyPI 包名 **`vcc-cli`**（当前 0.2.2），装出命令 `vcc`。注意 **PyPI 的 `vcc` 是无关的 Varnish 工具，不要装错**。命令：`login / whoami / datasets list|download controls / prep / submit / status / cancel / sample / skill install`，全部支持 `--json`。来源：https://pypi.org/project/vcc-cli/
- 控制数据：每 context 18,400 NTC 细胞（46 guides × 400）× 18,533 基因，中位 ~20k UMI/细胞。
- **提交硬约束**（wiki "Submission requirements (2026)"）：
  - 单文件覆盖 A/B/C；每 context 恰好 300 扰动 × 400 细胞（共 360,000，总上限 400,000）
  - **raw 整数计数**（禁止 log1p / normalize_total）
  - 单细胞总 counts ≤ 1,000,000
  - 基因集与顺序严格按 `gene_names.csv`（SAMD11 开头）
  - **密度上限 4,750,000,000 stored entries（≈13,200/细胞）**；稠密阵 6.67B 直接超限；**context 均值基线 ≈11,800/细胞，仅剩 ~10% 余量 → 必须 csr 稀疏存储 + 滤除 <1 CPM 的低表达基因、不存显式零**
  - 不得含 NTC 行；最终阶段 `--contexts D,E,F`
- 来源：https://vcc-cli-wiki.virtualcellchallenge.org/

## 5. cell-eval 包名澄清

- `cell-eval`（v1，0.8.2）：CLI `--profile`、`--ceiling`（split-half 估计指标上限）、`cell-eval prep/run`。https://pypi.org/project/cell-eval/
- **`cell-eval2`（最新 0.16.0）：竞赛官方打分器，`--preset vcc2026`，CPU 可跑，`[gpudge]` extra 可用 GPU 加速 DE**。https://pypi.org/project/cell-eval2/
- 指标规格书：https://github.com/ArcInstitute/cell-eval2/tree/main/docs/vcc2026_metrics

## 6. gpudge 澄清（重要）

- **gpudge 不是数据集**，是 GPU-only Mann–Whitney U 差异表达库（MIT，pip 可装，CUDA 12.6+，无 CPU 回退），cell-eval2 用它加速 DE。来源：https://github.com/ArcInstitute/gpudge
- CCL_2 是其 README 提到的 Arc 内部匿名化癌细胞系 CRISPRi 基准（子集 2.06M 细胞 × 4,672 guides；全量 5.54M 细胞 × 18,533 基因 × 5,095 扰动）。**基因面板宽度 18,533 与竞赛一致**（同一内部管线），但**无公开下载链接，公众拿不到，不可用作训练数据**。

## 对我们的直接影响

1. **L0.5/LLM 兜底线合法**：9/16 规则修订后，非 ML 生成的预测（启发式/LLM/手工规则）可提交——保留一条"纯统计+规则"提交线符合规则。
2. **装 `vcc skill install`**：官方 agent skill 可直接学习其工作流约定。
3. **密度帽是第一工程陷阱**：从第一个提交起就按"csr + 滤 <1 CPM"输出。
4. 工具链包名：`vcc-cli`（命令 vcc）、`cell-eval2`（--preset vcc2026）、`arc-state`。
