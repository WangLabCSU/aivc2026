## 官方工作流约定

```
vcc datasets list / download controls   # 官方数据包 ~406MB（controls h5ad + gene_names + pert_counts）
vcc prep pred.h5ad -g gene_names.csv --perts pert_counts.csv -o pred.vcc   # 本地校验+瘦身+打包
vcc submit pred.vcc -m "msg" [--wait]   # 上传（断点续传+校验和）并开始计分
vcc status <entry-id> --wait            # 等待出分，失败时非零退出
```

## prep 关键默认值与旗标（权威约束来源）

- `--dry-run`：只校验不打包（我们 CI gate 用它）
- `--expected-gene-dim 18533`（默认）、`--cells-per-pert 400`、`--contexts A,B,C`（最终阶段 `--contexts D,E,F`）
- `--require-counts`（默认开）：**raw counts 强制**，log-normalized 会被拒
- `--reject-controls`（默认开）：不得含 NTC 行
- `--max-counts-per-cell 1000000`；**另有 `--max-cell-dim 400000`（默认，疑似每细胞存储条目上限，比竞赛密度帽更严的单细胞约束）**
- `--no-verify-targets` / `--no-check-cell-counts`：调试用，勿在正式提交使用
- prep 还会 "slim"（自动瘦身），但我们的密度合规不能依赖它

## 认证（需用户操作）

- API key 在 <https://virtualcellchallenge.org/app/credentials> 生成（`vcc_pat_…`，只显示一次）
- 登录：`printf '%s' "KEY" | vcc login --token-stdin`（本人终端执行，token 不进聊天/历史）
- headless：`VCC_TOKEN` 环境变量
- `vcc whoami` 验证（应显示 account/team/"ready to submit"）

## 红线与陷阱

1. **一队同时只能一个在途提交**（第二个→HTTP 409）；崩溃任务等服务端 staleness 窗口清除。
2. **`vcc sample` 生成的随机文件一旦 submit 会真实消耗每日额度且分数极低**——只用于本地演练 prep，不提交。
3. 正式版 CLI 锁定生产 endpoint，`--endpoint` 仅源码构建可用（防钓鱼设计，勿尝试绕过）。
4. 提交必须 full-size：每 pert 恰好官方细胞数，服务器端先验，不符直接拒。
5. 上传/下载均断点续传 + 校验和验证。
